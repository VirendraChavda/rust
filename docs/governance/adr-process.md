# ADR Process

Architecture Decision Records (ADRs) capture concrete design decisions and tradeoffs.

## When ADR is required

- Finalizing major trait boundaries.
- Choosing runtime/state machine execution strategies.
- Selecting protocol and storage abstractions.
- Committing to compatibility-impacting patterns.

## Rules

- One decision per ADR.
- Keep status updated: proposed, accepted, superseded, deprecated.
- Link related RFC, PR, and implementation issues.
- Never rewrite accepted ADR history; supersede with a new ADR.
